# Vigil Credit Cabinet (Умный кредитный кабинет)

Прототип кредитного конвейера для малого и микробизнеса, оснащенный собственной системой контроля потоков данных на базе предметно-ориентированного языка (DSL) **Vigil**.

##  Главная особенность: Язык Vigil (Policy-as-Code)

Вместо использования тяжелых ИИ-моделей (LLM) для принятия кредитных решений, проект использует **детерминированный движок безопасности Vigil**, написанный на Go. Это гарантирует, что персональные данные (PII) и банковская тайна не могут утечь в публичные каналы из-за ошибки разработчика.

* **Lexer & Parser:** Собственный лексер и парсер, генерирующие AST (Abstract Syntax Tree).
* **Security Engine:** Проверяет уровни доступа (`secure`, `internal`, `public`), теги (`pii`, `bank_secret`) и ролевую модель (`RBAC`).
* **Аудит (SIEM):** Все инциденты безопасности логируются в файл `security_incidents.log` и выводятся в панель ИБ-офицера.

##  Запуск решения (Docker)

Для запуска прототипа на обычном ПК с Docker требуется выполнить одну команду в корне проекта:

```bash
docker compose up --build
```

После сборки приложение будет доступно по адресу: [http://localhost:8080](http://localhost:8080)

*(Альтернативный запуск без Docker: `go run ./cmd/vigil-core server`)*

##  Сценарии для проверки (Как тестировать)

В интерфейсе реализован сплит-скрин: слева — кабинет клиента, справа — рабочее место ИБ-офицера.

**Магия ИНН (ФНС Мок):** 
Введите ИНН `7700000000`. Система автоматически подтянет данные компании (ООО Ромашка, Директор Иванов).

**Предодобренный лимит:** 
Нажмите зеленую кнопку «Узнать мой предодобренный лимит». Система предложит до 3 000 000 ₽.

### Сценарий 1: Успешная выдача
* **Роль:** Сотрудник Аналитики (Банк).
* **Цель:** Оборотные средства. 
* **Сумма:** 1 000 000.

Нажмите «Отправить». Справа загорится зеленый граф, покажутся логи безопасности и код Vigil. Клиент получит одобрение и калькулятор платежей. Нажмите «Подписать договор (ЭЦП)» — появится окно выдачи кредита.

### Сценарий 2: Блокировка RBAC (152-ФЗ)
* **Роль:** Клиент (МСП). 
* **Сумма:** 500 000.

Отправьте заявку. Движок Vigil заблокирует передачу данных, так как у роли «Клиент» нет прав на канал `public_analytics`. На графе стрелка станет красной.

### Сценарий 3: Утечка данных (DLP)
* **Роль:** Сотрудник Аналитики.
* Поставьте галочку « Режим ошибки: Слить данные без маскировки».

Отправьте. Система выдаст критическую ошибку безопасности: попытка передать `secure` данные в `public` канал без маскировки.

##  Архитектура и допущения (Enterprise-контекст)

* **Backend:** Go (стандартная библиотека).
* **Frontend:** Vanilla JS, HTML, CSS (без тяжелых фреймворков для минимизации зависимостей).
* **Моки внешних систем:** Вместо реальной интеграции с CRM Альфа-Банка, ФНС и БКИ используются симуляторы (`internal/mock/fns.go`, `internal/scoring/scoring.go`).
* **Скоринг:** Детерминированная логика на основе запрашиваемой суммы и цели кредита. Ставки (Оборотный 21%, Инвестиционный 18.5%, Овердрафт 24%) соответствуют текущей рыночной ситуации и ключевой ставке.
* **Безопасность:** Отказ от LLM в пользу Policy-as-Code (Vigil). В банковской среде нейросети являются «черным ящиком» и несут риски утечки PII, поэтому для валидации потоков данных используется строгий компилятор.
